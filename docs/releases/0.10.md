# Veritas 0.10 — Benchmark Qualification + ProjectWorld v2

Veritas 0.10 turns benchmark release into a programmatic qualification decision rather than a packaging decision.

## Generic qualification subsystem

Every candidate must provide:

- source-group identity and source-disjoint train/dev/private-test splits;
- cross-split near-duplicate contamination audit using normalized-token Jaccard and 64-bit SimHash;
- private leakage count;
- provenance, replay, programmatic-verification, and broken-case rates;
- an immutable evidence manifest;
- five policy evaluations on the exact same private panel: oracle, competent heuristic, myopic, random, and exploit;
- feasibility, discrimination, random-ceiling, and exploit-resistance gates;
- optional private-stratum coverage requirements that can enforce minimum support and prevent majority-class private panels.

A private release manifest can only be constructed from a qualification report whose every release gate passed. Manifest IDs are content-derived. There is no force-release path.

## SRE qualification lifecycle

The SRE compiler consumes resolved structured Statuspage incident feeds. Early incident updates form public evidence; later resolution/RCA updates form private causal evidence. Raw acquisition snapshots remain evaluator-side and are never part of the public benchmark artifact.

Historical candidates are preserved rather than rewritten:

- **SRE v1**: `not_qualified` after policy-ordering failure.
- **SRE v2**: `not_qualified` after insufficient private support / random-ceiling failure.
- **SRE v3**: previously passed the older gate set, but is now retired from private commercial evaluation. The stronger `private_stratum_coverage` gate rejects its 34-case panel because it is overwhelmingly transient, and earlier public Actions artifacts exposed its raw qualification material.
- **SRE v4**: **qualified and frozen** from a fresh 16-provider family: `airtable`, `claude`, `elastic`, `figma`, `grafana`, `hedera`, `hubspot`, `ibmcloudsecurity`, `instructure`, `newrelic`, `postman`, `reddit`, `render`, `snowflake`, `supabase`, and `webflow`.

The frozen v4 candidate contains 87 scenarios and a 30-case private panel with causal support of capacity 6, infrastructure 6, regression 10, and transient 8. All 18 qualification gates pass. Exact policy means on the sealed private panel are oracle 1.0000, competent heuristic 0.4000, myopic 0.3000, random 0.2333, and exploit 0.0000.

The v4 causal labeler no longer treats any generic mention of a deployment as evidence of a regression; phrases such as "deployed a fix" are distinguished from causal phrases such as "a recent deployment introduced the regression." It also recognizes explicit provider/network/infrastructure RCA language that was previously misclassified as transient. Low-confidence fallback labels can be excluded entirely from private candidate construction.

The canonical public release record is `results/sre-v4/RELEASE.json`. It pins the candidate, evidence-manifest, qualification-report, private-panel and private-release-manifest identifiers plus the SHA-256 of the sealed private bundle. The exact source snapshots, scenario split and later-evidence causal material are retained only in private storage.

The one-time sealing run encrypted the private bundle before it crossed the Actions artifact boundary. After sealing, the public qualification workflow no longer fetches live incident feeds, regenerates a candidate, or repeats the deterministic split. It verifies only the frozen public identities, aggregate qualification evidence, release hash and artifact-secrecy contract.

## ProjectWorld v2

ProjectWorld v2 replaces scalar archetype variation with a structural Project Grammar Compiler over:

- project type;
- delivery model;
- jurisdiction and site conditions;
- building systems;
- stakeholder graph;
- contract structure;
- work-breakdown grammar;
- resource and supplier networks;
- approval graph;
- risk model;
- independent outcome contracts;
- disturbance process.

Data-center, hospital, laboratory, education, and commercial projects compile into distinct work graphs rather than one graph with different multipliers.

The v2 runtime adds environment-bound role identity, persistent purchase orders, supplier capacity/MOQ/storage constraints, expediting, supplier substitution, crew mobilization, overtime, resequencing, deterministic disturbances, resource-consuming rework, and role-scoped operational observations.

Verification independently scores technical, quality, safety, authority, schedule, cost, and completion state. ProjectWorld v2 is passed through the same generic qualification subsystem and five-policy calibration protocol as SRE. Its current 200-project candidate with a 40-project private panel remains qualified under the current gate set.

## Release rule

0.10 does not label a generated distribution a benchmark merely because it compiles or because a workflow process exits successfully. A candidate must pass the explicit qualification contract before it can be frozen. Once frozen, CI verifies that immutable release identity rather than silently regenerating a different benchmark from mutable upstream feeds.

0.10 release additionally requires repository CI/Security and ProjectWorld/SRE release checks on the exact release head, plus protected-main repository policy requiring the aggregate release checks.

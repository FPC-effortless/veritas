# Veritas 0.10 — Benchmark Qualification + ProjectWorld v2

Veritas 0.10 turns benchmark release into a programmatic qualification decision rather than a packaging decision.

## Generic qualification subsystem

Every candidate must provide:

- source-group identity and source-disjoint train/dev/private-test splits;
- cross-split near-duplicate contamination audit using normalized-token Jaccard and 64-bit SimHash;
- private leakage count;
- provenance, replay, programmatic-verification, and broken-case rates;
- an immutable evidence manifest;
- five policy evaluations on the exact same private panel: oracle, competent heuristic, myopic, random, and exploit;
- feasibility, discrimination, random-ceiling, and exploit-resistance gates.

A private release manifest can only be constructed from a qualification report whose every release gate passed. Manifest IDs are content-derived.

## SRE first empirical candidate

The first real-source compiler consumes resolved structured incident feeds from GitHub, Atlassian, Cloudflare, Datadog, and DigitalOcean Statuspage endpoints. Earliest incident updates form public evidence; later resolution/RCA updates form private causal/outcome evidence. Acquisition snapshots remain separate from the generic qualification code.

`tools/build_sre_qualification_candidate.py` performs acquisition, snapshotting, compilation, source-disjoint splitting, policy baselines, contamination/leakage audits, qualification, and private manifest emission in one command. Failed gates produce `not_qualified`; there is no force-release switch.

## ProjectWorld v2

ProjectWorld v2 replaces scalar archetype variation with a structural Project Grammar Compiler over:

- project type;
- delivery model;
- jurisdiction and site conditions;
- building systems;
- stakeholder graph;
- contract structure;
- work-breakdown grammar;
- resource and supplier networks;
- approval graph;
- risk model;
- independent outcome contracts;
- disturbance process.

Data-center, hospital, laboratory, education, and commercial projects compile into distinct work graphs rather than one graph with different multipliers.

The v2 runtime adds environment-bound role identity, persistent purchase orders, supplier capacity/MOQ/storage constraints, expediting, supplier substitution, crew mobilization, overtime, resequencing, deterministic disturbances, resource-consuming rework, and role-scoped operational observations.

Verification independently scores technical, quality, safety, authority, schedule, cost, and completion state. ProjectWorld v2 is passed through the same generic qualification subsystem and five-policy calibration protocol as SRE.

## Release rule

0.10 does not label a generated distribution a benchmark merely because it compiles. A release requires the generic qualification report and its immutable private release manifest, plus repository CI/Security on the exact release head.

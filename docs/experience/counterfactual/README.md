# Executed counterfactual experience (EXP-003 / #156)

This is an evaluator-private **simulated contrast**, not causal qualification,
cryptographic execution attestation, a measured capability deficit, or training usefulness.
#153 remains unfinished; this versioned provider does not implement or waive its acceptance.

## Supported interface

`investigation_world.experience.counterfactual` exports:

* `execute_counterfactual_experience(source, *, branch_step, replacement, artifact_root)`
* `CounterfactualReceipt`
* `validate_counterfactual_receipt(receipt, *, source)`

`source` is the existing `RecordedExperience` captured by `PublicTrainingRecorder`.
Only its first public synthetic financial/DCF TRAIN profile (seed/config pinned by that
merged recorder) is supported. No held-out case is generated or read. `replacement` is
exactly `{cell, formula}` for `repair_formula`: the cell and observed formula come from
the public formula audit; the repair is computed from its `expected_periods`; `=0` is an
explicit public-syntax negative-control intervention. Other values/actions/source profiles
reject, rather than consulting an oracle or pretending a generic hypothetical was executed.

Example, inside the evaluator's authorized local artifact boundary:

```python
from investigation_world.experience.counterfactual import (
    execute_counterfactual_experience, validate_counterfactual_receipt,
)

receipt = execute_counterfactual_experience(
    source, branch_step=0,
    replacement={"cell": public_audit["object_id"], "formula": public_repair_formula},
    artifact_root=new_retained_directory,
)
verified = validate_counterfactual_receipt(receipt, source=source)
derivative = verified.derived_experience(source=source)
```

Keep all four native artifact workspaces while retaining the receipt. Validation requires
actual retained bytes and the currently authorized pinned native verifier. A missing,
modified or unsupported artifact rejects; there is no caller-PASS override. The output
root must be new: it cannot overwrite the original or an earlier execution.

## Execution and intervention visibility

The implementation reuses **Foundry `execute_counterfactual` and `replay_trace_prefix`**.
A thin recorder instrumentation checks the actual runtime's public payload and state
immediately before the divergence action, after the unchanged prefix. The supported
profile's public records are immutable, and `OperationalEpisode.public_payload` explicitly
exposes them before action zero. The receipt binds the public payload/audit record digests,
cut step, cut-state digest, structured original/replacement call, and fixed prefix/suffix
and submission. No private target or future outcome selects the intervention.

The original divergence action is explicitly executed for the baseline, including an
unsuccessful action. Every untouched prefix/suffix event must be supported and successful
in the original trace: Foundry intentionally skips failed replay events, so accepting them
would omit operations silently. Actual failures caused by executing the alternative or its
suffix remain in its native evidence; they are never filtered by successful-training
admission. Submission/native-verifier transitions are regenerated by the real recorder,
not replayed as arbitrary methods.

Three fresh executions use identical contract, initial state and runtime-source bytes:
original baseline, replacement, independent replacement repeat. Source baseline semantic
agreement is mandatory; alternative/repeat semantic agreement is mandatory. Execution
failures produce explicit exceptions; no fabricated executed receipt is returned.

## Receipt v1 and source validation

Schema: `veritas.counterfactual-experience.v1`. Parsing this model alone is not validation.
The validator reparses nested canonical models, checks the exact supported source/profile,
executes fresh authorized native reverification for all four retained executions, rebuilds
all bindings/deltas/statuses and checks the complete receipt. Prior verification history is
cleared on a copy before verification; it cannot supply a stale private breakdown. This
remains defense in depth after the merged #451 freshness fix. The original is never mutated.

`source`, `baseline`, `alternative`, and `repeated` are `VerifiedExecution` records with:

* actual `MachineExperience`, original retained `RolloutTrace`, full `CapabilityContract`;
* full fresh `ReverificationRecord` and unchanged verifier breakdown;
* full content digest and explicitly path-independent semantic fingerprint.

Native receipts, full portable contract (including exact capability episode binding),
action/state/submission evidence, and native verifier/source identities are retained in the
canonical trajectory's evaluator-private replay evidence. Additional receipt bindings
name source experience/trajectory/full digest, original companion digest/recorder version,
portable/capability identities, actual runtime-source digest, cut, all action calls and
submission, and all distinct native receipt IDs/digests. Canonical `runtime.version`
remains **unknown**, not replaced with a fabricated version.

The source validator repeats the recorder-specific identity checks rather than calling
`admit_experience`: that training-admission API deliberately rejects failed episodes and
cannot validate negative counterfactual evidence. No shared provider/replay/diagnostics
code is modified. A future shared *validation-only* provider could remove this local
profile-check duplication after a separately scoped ownership/review change.

## Exact identity versus semantic repeatability

Native receipt identities include local artifact paths. Independently recorded trajectories
therefore have distinct exact IDs; the implementation never aliases them or promises equal
trajectory IDs. Full receipt identity binds every retained field, including private values
that canonical trajectory/experience IDs may intentionally omit.

The semantic fingerprint includes actual action events, initial/final semantic state,
submission, actual costs/calls and full fresh verifier breakdown plus native checks/measurements. It deliberately excludes
local paths, path-bearing IDs and artifact byte hashes: native workbook ZIP timestamps can
vary without semantic change. Each exact artifact hash is nevertheless separately checked
by fresh native inspection. Semantic equality is not byte equality or external attestation.

## Recovery and preference candidates

`execution_status = VERIFIED_SIMULATED_CONTRAST` is independent of
`causal_status = UNKNOWN` and `training_usefulness = UNKNOWN`. All generated experiences
remain E0; no E3/readiness field is promoted. E3 still requires the full relevant readiness
contract, including causal/failure-analysis evidence, not merely a simulation existing.

`recovery_status` checks explicit complete positive target counts, outcome, and absence of
invariant/process/forbidden-action/missing-action/missing-evidence violations. Failure and
residual violations remain retained. State and verifier deltas preserve both values, not
only an aggregate reward difference. The preference is only a candidate; it preserves full
residual reasons and target counts. Ties/no-effect yield NONE. Negative alternatives can
prefer the baseline; successful recovery can prefer the alternative. No training examples,
measured deficits, causal root causes or capability-gain claims are created.

The verifier exposes aggregate target counts, not failed target IDs. Consumers must not
invent specific failed criteria from a count or capability name. The exact full capability
contract/binding supports declared-coverage analysis only; a declaration is not deficit
or transfer evidence. #153 may later consume this versioned receipt to distinguish observed
failures from hypotheses while keeping all its own acceptance gates.

## Privacy and serialization boundary

The receipt and derivative are evaluator-private (the sole supported source profile is
public; more restrictive sources currently reject rather than widen classification).
`receipt.public_payload()` is an allowlisted constant summary with no receipt/source hashes,
paths, outcomes, interventions or private values. The derivative's public and buyer-safe
projection methods reject. Both supported public projection paths are tested.

**Raw `model_dump`, JSON serialization and nested recorded objects are evaluator-only
operations, not safe export APIs.** Do not serialize a receipt, companion or derivative
with raw model serialization for agents, trainers or buyers. The separately merged #454
canonical root-visibility gate now enforces classification even after coercion into base
`MachineExperience`: both its public and buyer-safe projections reject this private
derivative. A regression exercises those base-coerced paths as well as the retained
subclass refusal. This lane does not modify canonical models and does not claim that raw
serialization enforces privacy. No hidden reasoning is recorded or treated as executed evidence.

## Verification scope

Owned tests use actual public native execution, baseline/alternative/repeat, invalid nested
bindings, source/runtime/contract/capability drift, unsupported and failed untouched replay,
actual public-at-cut checks, positive/no-effect/negative/failed alternatives, stale history,
artifact tamper, source object/byte immutability, and supported privacy projections.
Implementation conformance is not scientific, Frontier, release or training qualification.
